# SuperWiki 工作区与 OSS 双向同步需求说明

版本：1.0

日期：2026-09-18

状态：首版产品需求基线，待实现

适用平台：Windows、macOS

本文整合工作区模型、用户自带 OSS、首次合并、日常双向同步及页面交互。文中的“应”“必须”表示首版验收要求，不表示软件当前已经实现。

## 1. 产品目标与已确认边界

### 1.1 产品定位

SuperWiki 是本地优先的 Markdown 文件夹编辑器。用户可以完全离线使用，也可以将本地工作区连接到自己配置的阿里云 OSS，在自己的多台电脑之间同步文件。

核心使用场景：用户在 Windows 上编辑，内容同步到 OSS 后，在 Mac 上继续编辑；任意一台电脑离线时，仍可读写已经保存在本机的文件。

### 1.2 已确认的产品决定

| 项目 | 首版决定 |
| --- | --- |
| 存储与编辑 | 每台设备保留实际本地文件，编辑和保存始终以本地文件为基础 |
| 云端存储 | 用户自行配置阿里云 OSS；SuperWiki 客户端负责同步流程 |
| 用户范围 | 同一个人的多台 Windows / macOS 电脑 |
| 首要能力 | 文件夹双向同步，包括新增、修改和删除 |
| 备份边界 | 暂不提供历史备份、历史版本恢复或云端回收站；接受误删传播到所有设备 |

SuperWiki 统一提供的云服务属于后续方向。首版不要求 SuperWiki 账号，也不提供在线知识库连接、多人实时协同或手机端同步体验。

### 1.3 本说明补齐的首版规则

为使需求可直接进入技术设计，以下细节按本文规定收敛：一次只同步当前打开的工作区；一个本地文件夹只能关联一个云端工作区；首次关联采用合并预览；日常并发修改需要处理冲突；失败和中断支持重试。

这些是本说明给出的产品默认规则。具体 OSS SDK、同步协议、元数据格式、扫描间隔和存储实现由后续技术方案确定。

## 2. 工作区模型

### 2.1 概念定义

| 概念 | 定义 |
| --- | --- |
| 本地工作区 | 用户在当前电脑上打开的一个本地文件夹 |
| 云端工作区 | OSS 中由 SuperWiki 管理的一组工作区文件及必要同步信息 |
| 同步关联 | 当前本地文件夹与某一个云端工作区之间的对应关系 |
| OSS 连接 | 当前设备保存的一组访问 OSS 的配置，可供多个工作区复用 |
| 同步基线 | 对已成功同步内容的记录，用于区分新增、修改、删除和并发修改；不提供历史内容恢复 |

工作区只有“仅本地”和“已关联云端”两种关系状态。初始化、等待同步、同步失败、存在冲突等属于运行状态，不另建工作区类型。

### 2.2 关联约束

1. 一个本地文件夹在同一时间只能关联一个云端工作区；首版不允许关联目录互相包含，避免同一文件被重复管理。
2. 一个云端工作区可以连接多台设备；同一设备首版只允许关联一个本地副本。再次连接时应引导打开已有副本。
3. 两台电脑的本地绝对路径可以不同，文件按工作区内的相对路径对应。
4. 云端工作区具有稳定身份，名称只用于展示。不得根据名称相同就自动建立关联。
5. 同一 OSS 连接可以容纳多个工作区，各工作区具有独立存储范围；工作区列表仅展示指定范围内的 SuperWiki 工作区。

示例：Windows 的 `D:\Notes` 与 Mac 的 `/Users/user/Documents/Notes` 可以关联到同一个“个人笔记”云端工作区。

### 2.3 工作区列表

开始页保留最近打开记录，展示工作区名称、本地路径和“仅本地 / 云同步”标识。每次只打开一个工作区，不增加多标签或多个工作区同时编辑的能力。

“关闭工作区”退出当前工作区；“从最近记录移除”只移除入口。两者均不表示删除本地文件或云端工作区。

## 3. 首版范围

### 3.1 包含的能力

| 能力 | 范围 |
| --- | --- |
| 本地使用 | 打开本地文件夹，不配置 OSS、不发起同步 |
| 开启同步 | 已有本地文件夹创建新的云端工作区 |
| 加入同步 | 下载已有云端工作区，或将已有内容的本地文件夹与其合并关联 |
| 日常同步 | 处理双方新增、修改、删除，以及外部工具产生的文件变化 |
| 状态与恢复 | 同步状态、差异与冲突处理、失败重试、初始化续接和断开关联 |

### 3.2 文件范围

同步用户选择的工作区内的普通文件及其相对路径，包含 `.md`、`.markdown`、图片、各级 `assets/` 和其他普通附件。其他文件按原始内容传输，不因此增加非 Markdown 编辑能力；图片仍为只读预览。

客户端凭证、当前设备的绝对路径、设备私有同步记录、传输临时文件和应用缓存不作为用户文件同步。必要的共享同步信息由客户端单独管理。

首版不跟随符号链接，不同步工作区外的引用文件、系统特殊文件、操作系统权限和扩展属性；空目录不作为独立同步对象。有文件的目录结构必须保留。遇到不可同步的文件，必须说明具体路径和原因，不得静默宣称全部同步完成。

### 3.3 本次不包含

- 历史备份、版本历史、回收站、撤销远端覆盖和整工作区快照恢复。
- SuperWiki 自营云服务、账号体系及多人实时协作。
- 在线知识库连接、Git 同步及多个云存储提供商。
- 独立后台常驻进程、应用退出后的同步及多个工作区并行同步。
- 扩展编辑器的文件管理能力、自动改写所有文档链接及自动内容合并。

同步可接收文件管理器或其他编辑器产生的新增、删除、重命名和移动，不要求同步首版同时增加对应的编辑器管理按钮。

## 4. OSS 配置与管理

### 4.1 配置项

| 配置项 | 要求 |
| --- | --- |
| 连接名称 | 供用户识别，例如“个人 OSS” |
| Endpoint | 用于连接用户的 OSS 服务地址 |
| Bucket | 工作区使用的存储空间 |
| 访问凭证 | 用户授权的 AccessKey ID / AccessKey Secret |
| 存储前缀 | SuperWiki 工作区使用的范围，提供统一默认值，并允许首次配置时指定 |

配置页提供“测试连接”和“保存”。测试结果说明服务是否可达、Bucket 和指定范围是否可访问；实际读写或删除权限不足时，必须展示明确的操作失败原因。

本地使用不要求填写配置。用户进入同步流程时，可以选用当前设备已有的 OSS 连接，或新建连接。

### 4.2 配置规则

1. 凭证仅保存在当前设备的安全凭证存储中，不进入工作区正文、共享同步文件或日志；另一台设备需要独立配置凭证。
2. 访问范围限定为用户授权的 Bucket 和前缀；工作区同步不得读写无关对象。
3. 更新同一存储位置的访问凭证不重建关联；改变 Bucket 或存储范围不能被当作普通凭证更新，首版通过断开后重新关联处理。
4. 使用 HTTPS，云端文件保持私有访问；本次不提供公开分享链接。
5. 同步不依赖 OSS 版本控制，也不自动修改用户已有 Bucket 的版本控制或历史保留配置。

## 5. 三类入口与核心用户流程

### 5.1 场景 A：仅打开本地文件夹

入口：开始页主按钮“打开本地文件夹”。

流程：选择文件夹 → 展示目录树 → 直接编辑。

工作区标记为“仅本地”。用户随时可通过工作区菜单开启同步，本地路径和已有文件保持原位。

### 5.2 场景 B：将本地文件夹同步到新工作区

入口：开始页“同步本地文件夹”，或已打开工作区的“同步 → 开启同步”。

1. 确定本地文件夹，并保存当前编辑内容。
2. 选择或配置 OSS 连接，填写云端工作区名称，默认使用本地文件夹名称。
3. 展示首次上传预览，包括文件范围和待上传数量。
4. 用户点击“创建并开启同步”，创建独立云端工作区并上传文件。
5. 完成首次上传后进入正常双向同步；失败时保留初始化进度，可重试。

不得覆盖同名云端工作区。同名时提示用户更换名称，或转到“连接已有云端工作区”流程，不自动合并。

### 5.3 场景 C：连接已有云端工作区

入口：开始页“连接云端工作区”，或已打开工作区的“同步 → 连接已有云端工作区”。

| 本地情况 | 产品行为 |
| --- | --- |
| 未打开本地文件夹 | 选择远端工作区，再选择本地保存位置；默认创建一个新的工作区子文件夹 |
| 目标文件夹为空 | 预览待下载文件，确认后下载并建立同步基线 |
| 目标文件夹已有内容 | 进入首次合并预览，不直接覆盖或清空任一端 |
| 本地文件夹已有关联 | 引导打开当前关联；切换远端前须断开原关联，不直接替换 |

用户在已打开的本地工作区内发起连接时，本地路径默认只读展示，明确表示本次操作针对当前文件夹。

## 6. 首次关联与合并规则

### 6.1 基本原则

首次关联时尚无共同同步基线。因此，某一端没有某个文件只表示“需要补齐”，不能解释为删除。

首次合并以文件相对路径和内容进行比较，不根据修改时间较新就自动覆盖。文件名中的大小写、目标系统不支持的名称以及文件与目录占用同一路径等情况，必须先校验。

### 6.2 差异分类

| 分类 | 条件 | 首次合并动作 |
| --- | --- | --- |
| 仅本地存在 | 相对路径仅在本地存在 | 上传到云端 |
| 仅云端存在 | 相对路径仅在云端存在 | 下载到本地 |
| 内容一致 | 两端相对路径和内容一致 | 不传输，记录一致状态 |
| 内容冲突 | 两端相对路径一致、内容不同 | 等待用户选择处理方式 |
| 路径冲突 | 大小写碰撞、不合法名称或文件/目录类型冲突 | 展示具体原因，提示在对应设备处理路径后重新扫描 |

首次合并不执行删除。路径冲突和未决定的内容冲突必须处理完，才能确认首次合并。

### 6.3 内容冲突处理

| 选择 | 本地结果 | 云端结果 |
| --- | --- | --- |
| 使用本地 | 保留本地内容 | 本地内容替换云端原文件 |
| 使用云端 | 云端内容替换本地原文件 | 保留云端内容 |
| 保留两份 | 原路径使用云端内容，本地内容另存为冲突副本 | 同时保留原文件与冲突副本 |

“保留两份”使用可识别的文件名，例如 `九月计划（本地副本-WindowsPC）.md`。如名称已存在，应生成不冲突的名称；重试同一次操作不能反复创建副本。

首次内容冲突默认不替用户选择。提供逐个处理和“剩余冲突保留两份”，批量操作不得改写用户已做出的选择。

冲突副本仅用于保留当前并发内容，不形成版本历史或备份服务。选择覆盖后，首版不提供找回被覆盖内容的入口。

### 6.4 图片与附件冲突

图片和普通附件遵循相同的三种选择。支持的图片提供双方预览，其他附件提供文件名、大小和来源信息；不提供图片编辑或二进制自动合并。

保留两份图片时，原路径仍指向云端版本，本地图片以新名称保存。页面提示检查 Markdown 引用；首版不承诺自动修正所有相对链接。

### 6.5 确认与执行

1. 确认页展示本地路径、云端工作区和 OSS 连接，并汇总上传、下载、覆盖、保留副本的数量；覆盖项可展开查看路径与方向。
2. 确认页说明“启用后，新增、修改和删除会同步到其他设备；当前不提供历史版本恢复”。无需在每次普通删除时重复确认。
3. 点击“合并并开启同步”前，仅允许保存用户当前编辑及读取差异，不得按预览计划修改远端或覆盖本地文件。
4. 执行前及执行过程中发现相关文件发生变化时，重新校验受影响的动作；旧的冲突选择不得直接覆盖后来产生的新内容。
5. 初始化完成后才进入正常同步。已经完成的传输可保留；未完成项可重试，不承诺一次合并中的所有文件整体回滚。

初始化期间的新编辑继续保存到本地，不允许下载的旧内容覆盖新编辑。新增变更进入后续同步处理；如仍有待处理项，不能显示“已与云端同步”。

## 7. 正常双向同步规则

### 7.1 基于共同记录判断变化

以下比较均以双方最近成功同步的内容为基准，包含第三台或更多设备经 OSS 产生的更新。

| 本地变化 | 云端变化 | 处理方式 |
| --- | --- | --- |
| 未变化 | 未变化 | 不传输 |
| 新增或修改 | 未变化 | 上传本地变更 |
| 未变化 | 新增或修改 | 下载云端变更 |
| 双方均修改，结果相同 | 双方均修改，结果相同 | 记录一致，不制造冲突副本 |
| 双方均修改，结果不同 | 双方均修改，结果不同 | 标记冲突，保留双方内容并等待选择 |

两端独立新增同一路径也使用上述内容比较规则。冲突出现后，仅暂停该文件的覆盖和删除动作，其他无冲突文件继续同步。

### 7.2 删除、重命名与移动

| 场景 | 处理方式 |
| --- | --- |
| 一端明确删除，另一端自基线后未修改 | 删除传播到另一端及其他设备 |
| 双方均明确删除 | 记录已删除，不反复执行 |
| 一端删除，另一端修改或存在未保存编辑 | 标记“删除与修改冲突”，提供“保留修改”或“确认删除” |
| 外部工具重命名或移动文件 | 首版可按旧路径删除、新路径新增同步，发生并发修改时继续按冲突规则处理 |
| 离线设备重新上线 | 先核对同步记录；未修改的旧文件不得把已删除文件自动重新上传 |

“保留修改”使修改后的文件重新存在并向其他设备同步；“确认删除”删除该冲突文件并继续传播。不得仅因应用刚启动时读取到旧副本，就撤销已发生的删除。

接受删除传播不等于将读取异常当作删除。网络错误、鉴权失败、列举不完整、磁盘不可读、工作区根目录丢失等情况，必须暂停相关判断并显示错误，不能触发批量删除。

从 Markdown 中移除图片引用不等于删除图片文件，只有图片文件本身被明确删除才传播删除。

### 7.3 本地编辑与外部变化

1. 保留现有 500ms 防抖本地自动保存；远端上传对短时间内的连续保存合并处理，不要求每次本地写入都对应一次上传。
2. 识别 SuperWiki、文件管理器和其他编辑工具产生的变化；远端落盘后刷新目录树及受影响的编辑和预览内容。
3. 当前文档自同步基线后没有本地变化、也没有未保存编辑时，可以应用远端新内容；存在已保存待同步的修改或未保存编辑时，先保留最新内容，再参与冲突判断。
4. 下载和本地写入不得让用户读到半个文件；文件内容未完整传输和校验完成前，不标记该项同步成功。
5. 图片与文档均完成后才显示整体同步完成；传输中暂缺的资源显示待同步状态，不能被当作文件删除。

### 7.4 自动触发与手动操作

打开已关联工作区、恢复网络、本地文件变化及应用回到前台时，应自动检查或安排同步。工作区保持打开时应能持续接收远端变化，不要求另一台设备反复手动点击。

提供“立即同步”和失败后的“重试”。手动操作优先发起检查，不跳过冲突处理，也不强制一端覆盖另一端。

首版不承诺固定秒数内同步完成，实际耗时取决于网络、文件数量和大小。扫描及传输不能阻塞编辑输入、目录浏览和本地保存；不能因用户持续输入就无期限推迟所有上传。

## 8. 页面与交互设计

### 8.1 开始页

主入口为“打开本地文件夹”。次级的“云同步”区域提供“同步本地文件夹”和“连接云端工作区”。下方展示最近工作区。

用户不应在打开纯本地文件夹前被要求配置云服务或选择同步策略。

### 8.2 工作区菜单与同步设置

| 当前关系 | 展示的主要操作 |
| --- | --- |
| 仅本地 | 开启同步、连接已有云端工作区 |
| 初始化中 | 查看初始化进度、查看失败项、重试 |
| 已关联云端 | 查看同步详情、立即同步、处理冲突、断开同步 |

同步设置显示本地路径、云端工作区名称、OSS 连接和最近同步结果。技术参数集中放在 OSS 连接配置中，不占据日常编辑界面。

### 8.3 “连接已有云端工作区”三步弹窗

编辑器保留在后台，使用一个居中的三步弹窗完成选择、预览与确认。左右对比空间不足时改为上下排列，不能缩小文字到难以阅读。

| 步骤 | 页面内容 | 主按钮与门禁 |
| --- | --- | --- |
| 1. 选择工作区 | 当前本地文件夹、OSS 连接、云端工作区列表；列表具备加载、空结果和失败重试状态 | “检查文件差异”；未完成选择、保存失败或连接不可用时不能继续 |
| 2. 合并预览 | 双方位置、上传/下载/一致/冲突数量、文件差异列表；冲突优先展示 | “查看合并结果”；存在未处理内容冲突或路径冲突时禁用，并显示剩余数量 |
| 3. 确认连接 | 最终操作汇总、覆盖方向及文件明细、同步删除规则 | “合并并开启同步”；同时提供“返回预览” |

检查文件差异时显示加载状态，避免重复发起。更换云端工作区后，之前的预览与冲突选择失效，需要重新扫描。

### 8.4 差异与冲突交互

1. 文件列表展示相对路径、动作和处理状态；已一致文件可以折叠，上传与下载方向必须有文字或图标说明。
2. 点击“比较”在当前列表内展开双方内容，不跳转离开连接流程；Markdown 使用文本差异，图片使用双方预览。
3. 展开区提供“使用本地”“使用云端”“保留两份”，选中后立即说明结果，例如“云端文件将被本地内容替换”。
4. 提供“剩余冲突保留两份”，并实时更新剩余冲突数量和确认页统计；已选择的项允许重新调整。
5. 日常同步复用相同的冲突交互；删除与修改冲突使用对应的两项决定，不显示不适用的三项选项。

### 8.5 取消、执行中关闭与完成

确认执行前的“取消”或关闭弹窗，不建立新的同步关联、不执行合并动作；已保存的用户编辑保持保存状态。

确认执行后，展示“正在初始化同步”，包含当前方向、进度和失败项。此时关闭进度弹窗只是返回编辑器，任务仍在当前工作区内继续，不再称为“取消并回滚”。

首次合并完成且无待处理项时，显示“已连接云端工作区”，并返回编辑器的同步状态入口。若网络中断，显示原因和“重试”；用户可返回编辑器，工作区保留“初始化待完成”状态。

## 9. 状态模型与文案

### 9.1 本地保存与云同步分开

本地保存继续使用保存中、已保存、保存失败等现有状态。云同步状态不得替代本地保存状态。

示例：“已保存到本地 · 等待同步”。OSS 失败不能显示为本地保存失败；本地保存失败也不能显示为该文档已经成功同步。

### 9.2 工作区同步状态

| 状态 | 含义 | 用户可用操作 |
| --- | --- | --- |
| 仅本地 | 没有云端关联 | 开启同步、连接已有工作区 |
| 正在初始化同步 | 首次上传、下载或合并进行中 | 查看进度、返回编辑器 |
| 初始化待完成 | 首次同步未全部完成 | 查看原因、重试 |
| 等待同步 | 已有本地变更或离线待处理项 | 继续编辑、立即同步 |
| 正在同步 | 正在检查、上传或下载 | 查看详情、继续编辑 |
| 已与云端同步 | 本次检查与传输结束，无已知待处理项 | 查看最近成功时间、立即同步 |
| 同步失败 | 某些操作因网络、权限或文件问题未完成 | 查看失败文件和原因、重试 |
| 有冲突 | 需要用户决定内容 | 查看并处理冲突 |

“已与云端同步”描述当前设备与云端的最近成功状态，不代表所有其他设备已经收到。状态入口同时保留最近成功检查时间，不能在断网后继续表达实时一致。

失败、冲突和待处理项可能同时存在。总入口优先显示需要用户行动的状态，详情中分别列出，不用一个错误覆盖其余信息。

## 10. 离线、重试与关联生命周期

### 10.1 离线与中断

本地文件始终可用。待同步变更、已完成的初始化进度及必要同步记录需要持久化，应用重启后可继续处理。

恢复时重新检查双方当前状态，不能盲目重放过期覆盖或删除。重复重试同一项，不得产生内容损坏、重复副本或错误的成功状态。

### 10.2 关闭与切换工作区

切换文件或工作区前，保留现有的编辑器内容同步和待保存内容落盘流程。本地保存失败时保留编辑并阻止会丢失内容的切换。

首版仅为当前打开工作区安排同步。关闭工作区、切换到另一个工作区或退出应用时，应保存必要进度并妥善结束在途操作；重新打开后自动核对并继续。无需等待云端恢复才能关闭应用，但必须清楚显示仍有内容未同步。

### 10.3 断开同步

“断开同步”停止当前本地文件夹的云端关联，保留本地与云端的文件，不向其他设备发送文件删除。

断开前展示当前待处理数量；存在尚未落盘的本地编辑时先完成本地保存。用户确认断开后停止同步调度，妥善结束在途操作并清理关联状态，不能在界面显示已断开后继续发起新写入。

断开后重新连接，按首次关联重新比较，不用已经失效的记录推断删除。首版不提供客户端“删除云端工作区”管理入口。

## 11. 必要实现约束

本节规定可靠性边界，不指定技术栈选型或具体 OSS API 调用方案。

### 11.1 数据与并发

1. 必须持久化能够识别已同步版本、明确删除和并发修改的必要信息；不做历史备份不代表可以只比较两端当前文件是否存在。
2. 多台设备同时上传同一路径时，必须保留并识别竞争修改，不能采用没有冲突检测的“最后上传者覆盖”。只有用户的冲突选择才能明确舍弃另一份内容。
3. 必须区分首次建立关联、正常同步和初始化中断，防止空目录、部分下载或重试触发错误删除。
4. 每个文件的传输与应用需要可验证、可重试；不要求所有文件具有一次整体提交的事务效果。
5. OSS 的对象存储能力不替代客户端的变化识别、冲突处理和调度逻辑；SDK 和协议能力必须基于官方文档验证，不能直接假定与其他对象存储 API 完全相同。

### 11.2 本地文件与现有架构

文件读取和落盘继续通过 Rust 本地文件服务，不通过前端 Node API 或浏览器文件系统接口绕过现有路径边界。

远端路径不能被直接拼接后写入。下载新增文件、目录创建及删除操作需要相应的安全路径校验，拒绝路径越界和符号链接逃逸；不能为了同步放宽现有 Markdown 编辑保存限制。

支持附件原样同步不等于允许将非 Markdown 文件作为 UTF-8 编辑内容覆盖。目录性能、编辑器按需加载、图片只读、预览滚动及快速切换前保存等现有要求继续作为回归标准。

### 11.3 性能与可观察性

同步处理只传输需要变化的文件。扫描、网络传输和重试不能阻塞主编辑交互，不能形成无限快速重试。

同步详情至少能回答：正在上传还是下载、哪些文件未完成、失败原因是什么、何时最近成功同步、用户下一步可做什么。错误信息不得包含访问密钥或完整签名凭证。

## 12. 验收标准

以下场景必须在 Windows 与 macOS 的真实跨设备环境中验证；静态页面或模拟 OSS 成功不能替代端到端验收。

### 12.1 工作区入口

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| W01 | 不配置 OSS 打开本地文件夹 | 正常读写和预览，不要求登录或联网 |
| W02 | 已有本地文件夹创建云端工作区 | 用户确认后上传，文件及相对路径完整，失败可重试 |
| W03 | 空文件夹连接已有工作区 | 下载云端文件，不把本地缺失当成删除 |
| W04 | 非空文件夹连接已有工作区 | 正确分类四种内容差异，冲突决定前不能执行首次合并 |
| W05 | 重复关联或路径冲突 | 不创建重复关联；同名工作区、大小写碰撞和类型冲突有明确处理提示 |

### 12.2 双向同步与文件范围

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| S01 | 两台电脑轮流新增和修改文件 | 自动交换变更，最终内容一致，双方本地路径可不同 |
| S02 | Markdown、嵌套 assets 和普通附件 | 文件内容及相对路径保留，图片可正常显示，非 Markdown 不出现编辑能力 |
| S03 | 一端删除，另一端未修改 | 删除传播；离线的第三台设备恢复后不自动复活未修改的旧文件 |
| S04 | 文件管理器重命名、移动或修改文件 | 变化被识别并同步；目录树及当前文档刷新正确 |
| S05 | 离线编辑后退出并重启 | 本地编辑保留，恢复网络后自动处理待同步内容，无错误成功状态 |

### 12.3 冲突与首次合并

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| C01 | 同路径不同内容 | 三种选择的结果符合规则，未处理完时下一步禁用，最终覆盖清单准确 |
| C02 | 保留两份及批量处理 | 双方内容保留到两端，副本命名不碰撞，重试不反复生成副本，批量操作不覆盖已选项 |
| C03 | 预览后又发生编辑或远端更新 | 受影响动作重新核对，旧预览不覆盖新内容；其他无冲突内容可继续处理 |
| C04 | 删除与修改同时发生 | 保留待处理内容，按“保留修改 / 确认删除”结果收敛；普通删除仍可自动传播 |
| C05 | 两台设备同时新增或修改同一路径 | 相同内容不制造冲突，不同内容不会静默丢失；有未保存编辑时也满足此要求 |

### 12.4 中断、状态与现有能力

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| R01 | 断网、鉴权失败、部分列举或本地目录不可读 | 显示具体错误，不推断批量删除，不影响已经可用的本地文件编辑 |
| R02 | 初始化中断、关闭弹窗、退出后重开 | 保留已完成项，重新检查未完成项；关闭弹窗不假装回滚，重试不损坏内容 |
| R03 | 确认前取消及完成后断开同步 | 取消不执行合并；断开保留两端文件，且不再发起新同步写入 |
| R04 | 同步期间快速切换文件、工作区或模式 | 当前编辑内容不丢失；本地保存状态与云端同步状态表达准确 |
| R05 | 长文档、大目录、图片和代码块 | 现有编辑、预览、目录按需渲染与语言按需加载无明显回退，同步不阻塞输入 |

## 13. 交付与下一步

首版交付以本文的用户流程和验收标准为准。讨论中的交互草图用于说明三步弹窗、冲突展开及确认方式，其中的文件名、设备名、计数和模拟进度均为示例，不构成生产数据或性能承诺。

下一步进入技术方案设计：确定 OSS 访问方式、工作区身份与同步记录、并发和删除协议，再据此拆分 Rust 文件服务、同步调度、前端状态和页面任务。技术方案应先证明首次合并、离线删除与并发冲突可以可靠收敛，再进入实现。

不以实现阶段顺手添加历史备份、云服务账号或多人协同；这些另行形成后续需求。
