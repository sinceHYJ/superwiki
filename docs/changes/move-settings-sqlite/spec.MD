# 系统设置统一保存到本地 SQLite — 需求澄清

状态：本轮需求澄清完成，配置范围、工作区列表规则、密钥存储、旧数据边界及异常处理均已确认；尚未进入技术方案或代码实现阶段。

## 1. 背景与目标

当前 SuperWiki 的系统设置分散保存在本地 JSON 文件和 WebView localStorage 中，OSS 密钥保存在系统凭据库。用户希望将这些配置及 OSS 密钥统一保存到本地 SQLite 数据库。

本次改动的目标：

1. 系统设置拥有统一的本地持久化来源。
2. 用户修改设置后，重启应用仍能恢复已成功保存的设置。
3. 设置的含义、操作入口与生效方式保持现有行为。
4. 在 SQLite 中持久保存工作区列表，并保留工作区与其收藏、最近编辑记录的归属关系。

本文用于明确“哪些配置改存 SQLite、配置如何归属、用户会感知到什么”，不确定数据库结构、依赖选型、接口、文件路径或实现步骤。

本次“迁移”指更换配置的保存与读取方式，不包含将旧版本已经保存的数据搬入 SQLite，也不考虑旧版本用户的升级过渡。

## 2. 当前配置范围

以下清单列出当前保存位置、已确认的迁移范围及新增的持久化数据。

### 2.1 系统设置页面中的配置

| 分类 | 配置项 | 当前保存位置 | 本次范围 |
| --- | --- | --- | --- |
| 基础 | 打开的 Tab 数量上限、自动保存开关 | WebView localStorage | 迁入 SQLite |
| 外观 | 主题色、内容宽度 | WebView localStorage | 迁入 SQLite |
| 快捷键 | 自定义快捷键，包括恢复默认后的配置 | WebView localStorage | 迁入 SQLite |
| OSS 同步 | 启用状态、区域、Endpoint、Bucket、远端目录、AccessKey ID | 本地 `oss-sync.json` | 迁入 SQLite |
| OSS 同步 | AccessKey Secret | 系统凭据库 | 迁入 SQLite，不再使用系统凭据库 |

“关于”页面展示的版本信息不属于用户配置，不在本次迁移范围内。

### 2.2 设置页面以外的持久化数据

| 数据 | 当前保存位置 | 本次范围 | 配置归属 |
| --- | --- | --- | --- |
| 工作区列表 | 当前未持久保存列表，仅记录上次打开的工作区 | 新增 SQLite 持久化记录 | 应用级，保存多个工作区的记录 |
| 上次打开的工作区 | WebView localStorage | 迁入 SQLite | 应用级，记录上次打开的工作区 |
| 收藏文档 | WebView localStorage | 迁入 SQLite | 工作区级，每个工作区分别保存 |
| 最近编辑记录 | WebView localStorage | 迁入 SQLite | 工作区级，每个工作区分别保存 |
| 主题色历史迁移标记 | WebView localStorage | 改由 SQLite 保存，不导入旧版本标记值 | 应用级 |

上述五项已明确纳入范围。收藏文档和最近编辑记录属于各自工作区的配置，不合并为应用全局的收藏列表或最近编辑列表。

### 2.3 工作区配置的行为边界

1. 切换工作区时，仅展示当前工作区的收藏文档和最近编辑记录。
2. 在某个工作区收藏、取消收藏或产生最近编辑记录，不影响其他工作区的数据。
3. 关闭工作区不等于删除该工作区的收藏和最近编辑配置；再次打开该工作区时，按现有有效文档筛选规则恢复其记录。
4. SQLite 中保存的记录须保留各条记录与工作区的归属关系，不串用或混合不同工作区的数据。
5. 上次打开的工作区与主题色历史迁移标记保持应用级语义；SQLite 中已保存的主题选择不应在再次启动时被历史默认值调整覆盖。

### 2.4 工作区列表

SQLite 需要保存工作区列表，能够记录多个工作区，而不只是覆盖保存最后一次打开的工作区。每个工作区生成独立 ID，其他数据通过该 ID 关联工作区；本地文件夹路径同样保持唯一，用于判断是否已经记录该工作区。

1. 成功打开工作区时，若该路径尚无记录，则新增工作区记录并生成 ID。
2. 重复打开同一路径的工作区或文件夹，复用已有记录及其 ID，不新增重复记录，也不生成新 ID。
3. 工作区列表不存在删除操作；关闭或切换工作区不删除列表记录。
4. 已记录的工作区即使后续无法打开，也不自动从列表删除。

工作区列表与“上次打开的工作区”是两个不同概念：前者保存工作区集合，后者记录最近使用的工作区。已成功保存的列表在应用重启后仍然存在，收藏文档和最近编辑记录须能对应到所属工作区。

本条需求只确认工作区列表的持久化及上述维护规则，不直接代表新增多工作区同时打开能力或工作区管理界面。

## 3. 需求要求

### R1. 统一保存与读取

纳入范围的设置及 OSS 密钥使用本地 SQLite 作为持久化来源，不再从旧 JSON、localStorage 或系统凭据库读取或保存，也不因旧数据仍然存在而恢复旧值。

“配置全部迁移”指应用运行时的用户配置，不包括项目构建配置、应用打包配置等仓库文件。

### R2. 保持设置行为

设置页面的字段、默认值、有效值限制、保存操作及生效时机沿用现有行为，不改变自动保存、快捷键或 OSS 同步的业务行为。此要求不包含恢复旧版本已保存的配置。

读取设置期间，不得将临时默认值保存为用户设置，覆盖已有值。

OSS 配置页面的存储说明应反映密钥保存在本地 SQLite 的事实，不再显示“密钥保存于系统凭据库”。已保存密钥时，留空不修改密钥的现有操作语义保持不变。

### R3. 初始化与旧数据边界

不考虑旧版本用户过渡，不提供旧数据兼容流程：

1. 不导入旧 JSON 或 localStorage 中的设置、工作区、收藏、最近编辑记录及主题色历史迁移标记，也不导入系统凭据库中的旧 OSS 密钥。
2. SQLite 尚无相应设置时使用现有默认值；工作区列表初始为空，尚无上次工作区、收藏或最近编辑记录时按未设置或空记录处理。SQLite 中尚无 OSS 密钥时，按未配置处理，需要用户填写后保存。
3. SQLite 已保存的配置在后续启动时继续读取，不与旧存储进行合并、比较或回退。
4. 不设计旧数据备份、清理、升级兼容或降级兼容流程；本次不要求删除现存旧数据。

### R4. 保存可靠性与失败反馈

成功保存的设置在正常关闭、立即重启后仍保持一致。保存失败时，应让用户知道哪些修改尚未持久化，不得表现为保存成功。

SQLite 配置读取失败时，阻止进入应用主界面，显示明确的失败提示并提供重试入口。

1. 重试成功后，使用读取到的配置进入应用。
2. 重试仍失败时，保留失败提示及重试入口，继续阻止进入应用。
3. 失败期间不得清空或重置已有配置，不提供使用默认配置跳过错误的入口，也不回退到旧存储。
4. 首次使用时尚无配置属于正常初始化，按现有默认值和空记录进入应用；数据库无法打开或已有配置无法读取属于失败，不得按“无配置”处理。

### R5. 本地性与数据边界

配置保留在当前设备，不新增账号、远程配置服务或配置云同步。Markdown 正文、图片及其他工作区文件不迁入数据库。

AccessKey Secret 与其他 OSS 配置统一保存在本地 SQLite 中。OSS 配置保存、已配置状态判断及同步所需的密钥读取均不再依赖系统凭据库，也不在 SQLite 不可用时回退到系统凭据库。

## 4. 本次不包含

1. 新增设置项、重新设计设置页面或修改设置的业务含义。
2. 将文档正文、图片等内容改为数据库存储。
3. 新增配置导入导出、跨设备同步或备份管理界面。
4. 旧版本用户过渡、旧数据导入与备份清理，以及升级或降级兼容。

## 5. 澄清结论

Q1 已确认：上次打开的工作区、收藏文档、最近编辑记录和主题色历史迁移标记全部改由 SQLite 保存；收藏文档与最近编辑记录按工作区分别保存。

Q2 已确认：OSS 密钥也保存在 SQLite 中，不再使用系统凭据库。

Q6 已确认：SQLite 持久保存工作区列表，与上次打开的工作区分别记录；每个工作区具有独立 ID，其他数据按 ID 关联，路径也唯一。成功打开新路径时新增，重复打开同一路径复用已有 ID，列表记录不删除。

Q3、Q4 已关闭：不考虑旧版本用户过渡，不导入旧数据，也不要求旧数据备份或清理。

Q5 已确认：SQLite 配置读取失败时阻止进入应用并提供重试；读取成功后方可进入，不允许使用默认配置跳过错误。

## 6. 验收场景

以下场景作为本次需求的验收依据。

| 场景 | 预期结果 |
| --- | --- |
| SQLite 中尚无配置 | 使用现有默认设置；工作区列表为空，上次工作区未设置，收藏和最近编辑为空；修改并成功保存后，重启可恢复 |
| 保存多个工作区的列表后重启 | 列表记录均能恢复，能够对应各自本地文件夹，不被上次打开的工作区单条记录替代 |
| 首次成功打开某路径的工作区 | 列表新增工作区记录并生成独立 ID，路径唯一；其他数据通过该 ID 关联 |
| 多次打开同一路径的工作区，包括重启后再次打开 | 始终复用同一条记录及其 ID，不产生重复记录；收藏和最近编辑仍通过同一 ID 归属该工作区 |
| 关闭、切换工作区或已记录的工作区无法打开 | 列表记录保留，不发生手动或自动删除 |
| 修改基础、外观、快捷键设置 | 当前行为与改动前一致；重启保留新值；恢复默认快捷键后也能持久保留 |
| 修改并保存 OSS 配置及密钥 | 配置与密钥保存到 SQLite；重启后字段、启用状态及密钥已配置状态正确；测试连接和同步使用 SQLite 中的密钥，不访问系统凭据库 |
| SQLite 已保存 OSS 密钥，编辑其他 OSS 配置时密钥留空 | 保留 SQLite 中已保存的密钥，不清空、不改读系统凭据库 |
| 系统凭据库仍有旧 OSS 密钥，但 SQLite 中没有 | 按密钥未配置处理，不自动导入或使用旧密钥；用户填写并保存后方可使用 |
| 旧 JSON 或 localStorage 中仍有配置 | 不导入、不读取旧值；SQLite 无值时使用默认值或空记录，有值时读取 SQLite |
| SQLite 已保存配置无法读取或数据库不可用 | 阻止进入应用主界面，提示失败并提供重试；不清空、不重置已有数据，不以默认配置跳过错误 |
| 配置读取失败后重试成功 | 使用成功读取的配置进入应用，保留原有设置及工作区数据 |
| 配置读取失败后重试仍失败 | 继续阻止进入应用，保留失败提示和重试入口，不回退到旧存储 |
| 修改设置后立即正常关闭应用 | 已报告保存成功的配置在下次启动时仍然存在 |
| 在 SQLite 中保存上次工作区及主题色历史迁移标记后重启 | 上次工作区及标记可正确恢复；已保存的主题选择不被历史默认值调整覆盖；关闭工作区后重启不会恢复已清除的上次工作区 |
| 在工作区 A 修改收藏或产生最近编辑记录，再切换到工作区 B | B 仅展示自身记录，A 的操作不改变 B 的配置；切回 A 后可恢复 A 的记录 |
| 关闭工作区后重新打开或重启应用后再次打开 | 按现有有效文档筛选规则恢复该工作区的收藏与最近编辑记录；已取消的收藏不会因旧数据仍存在而恢复 |
| 使用新存储后继续修改配置 | SQLite 成为范围内配置及 OSS 密钥的持久化来源，旧 JSON、localStorage 和系统凭据库不再随操作更新；设置页面不再提示密钥保存在系统凭据库 |

## 7. 当前决策状态

已确认：将系统设置中原本保存在 JSON 和 WebView localStorage 的配置，以及上次打开的工作区、收藏文档、最近编辑记录、主题色历史迁移标记改由本地 SQLite 保存，并新增工作区列表的持久化记录。工作区列表与上次打开的工作区分别记录，每个工作区生成独立 ID，其他数据通过 ID 关联，路径同样唯一；重复打开复用已有 ID，记录不删除。OSS 密钥也统一保存在 SQLite 中，不再使用系统凭据库。收藏文档与最近编辑记录属于工作区级配置，按工作区分别保存和展示。不考虑旧版本用户过渡，不导入旧数据。当前阶段只编写需求描述，不实施代码改动。

异常处理已确认：SQLite 配置读取失败时阻止进入应用并提供重试，读取成功后方可进入；首次使用时无配置仍按默认值正常初始化。

当前无待确认项。本轮需求澄清完成，后续可依据本文编写技术方案；当前阶段不实施代码改动。
